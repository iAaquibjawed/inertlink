LinkVerify smoke page

Hover each link and check the badge against the expectation beneath it.

Nothing here is live malware. Every "dangerous" link uses RFC 2606 reserved names (example.com, .invalid, .test) or RFC 5737 documentation IPs. None resolve. Do not ever add a real malicious URL to this file — hovering must be safe, and it is only safe because these go nowhere.

Badges only appear once you grant access to this page. Open the LinkVerify popup and press Turn on for this site — the extension declares no static content script (ADR-0003), so nothing runs anywhere until you allow it. Check the console for [linkverify] active on … to confirm it is running.

Serve this page over http, not file://. Run npm run smoke and open http://localhost:8787/phishing-sandbox.html. A file URL has an opaque origin that cannot be written as a match pattern, so the popup has nothing it can request access to.

Should read Safe

  • example.com Plain HTTPS, no signals.
  • Documentation Subdomain depth is normal.

Should read Caution

  • http://example.com/login non-https on a login path.
  • example.com:8081/signin nonstandard-port.
  • a.b.c.d.e.example.com excessive-subdomains.
  • Shortened link url-shortener — destination unknown, not necessarily bad.
  • invoice-2026.zip suspicious-tld — the TLD collides with a filename extension.
  • Continue encoded-obfuscation — a second address hidden in the query.

Should read Danger

  • https://example.com/verify userinfo-trick — real host is internal.invalid.
  • Sign in to your account ip-host on a login page.
  • example.com billing deceptive-subdomain — brand is a subdomain of another host.
  • exarnple.com typosquat — "rn" reads as "m".
  • https://example.com/reset text-href-mismatch — visible text lies about the destination.
  • Sign in to PayPal typosquat — digit-for-letter homoglyph against a real brand.
  • Open document local-blocklist — bundled list hit, decisive on its own.
  • Click to continue javascript: with a real body — Caution, not Danger. It runs in this page's origin, which the site already controls.

Should read Safe

  • google.com allowlist — bundled known-safe domain, and never sent to any provider.
  • user.github.io github.io is a public suffix, so this is zero subdomains deep, not two.

Submit controls and InertLinks

  • A form submit button. Amazon's cart "Delete" and "Save for later" are exactly this — <input type="submit">, no href. Clicking still leaves the page, so the destination must be checked. Should read Danger.
  • A <button> with no type — defaults to submit. Should read Safe.
  • type="button" navigates nowhere. Must stay silent.
  • Share Amazon's cart "Share" is an <a href="#">. It reads as an InertLink — the anchor presents itself as a link (pointer cursor, a URL in the status bar), so silence there is indistinguishable from the extension being broken.
  • See more categories Inert placeholder. Amazon's cart has fourteen of these. Also an InertLink — never Danger.

Edge cases the badge must survive

  • Very long host Host must truncate in the middle, keeping the TLD visible.
  • Link at the right edge Badge must flip left instead of overflowing the viewport.
  • Anchor wrapping an image — hover target is not text.
